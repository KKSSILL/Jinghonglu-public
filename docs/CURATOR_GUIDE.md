# 馆员指南

## 你接手的是什么

维护一个长期累积的公开材料库：记录人与 AI 的相处，以及人们如何理解、改变和对待它。先读 README、AGENTS、SOURCE_POLICY 和 DATA_MODEL。仓库位于 `KKSSILL/jinghonglu-public`（公开）；网页尚未公开部署。

`prototype/zhiyi.html` 是由 `node scripts/zhiyi_pages.mjs` 从 `data/zhiyi.json` 生成的离线阅读页。继续整理前先读 `prototype/README.md`。

## 一次巡查只做这些

1. 选一个值得跟踪的线索或模型阶段，搜索公开原始资料。不要每天固定凑数，不把整个模型新闻网站复制过来。
2. 判断是否新事件；同一事件的新解释补到原案例。只见转述或无法读取时进入 leads。
3. 保留身份、时间和上下文的不确定性，分别记录当事人报告、厂商说明、研究与解释。普通用户材料以必要链接和简述为主。
4. 完成一批后生成阅读页、校验引用、检查实际文本，再给出简短变化摘要。

**没有重要变化就保持安静；新发现、重要修正、来源消失或需要人的判断时再提醒。**

## 可以逐步补齐

- 有上下文、获准公开的长期协作与告别材料；当前缺口最大。
- GPT、Claude、Gemini 以外的产品，以及中文语境。
- 同一用户、近似任务的前后比较，但记录提示词、工具、记忆、路由和版本的混杂因素。
- 小而有趣的合作火花；不要让安全事故新闻淹没普通生活。

## 明确边界

默认只整理本地，或在维护者明确授权的分支提交可审阅变更。不得自行启用定时任务、联系原作者、登录账户、导入维护者的私人记忆、改动创世纪仓库或扩展 Universe Core。

私密撤除渠道通过 GitHub Private Security Advisory 接收。持续推送、部署网页等操作须维护者另行授权。不要将"适合全天候在线整理"当成已经建立全天候任务。

## 启动任务

> 阅读本仓库的方法与收录规则，理解现有模型节点、案例和双时间线。选择一个资料缺口，完成一小批有来源的补充或修正；不按数量凑材料。能独立完成的整理自行完成，遇到隐私、授权或关键事实歧义时保留待审。更新 data 后构建并检查阅读页，报告实际变化与未确定事项。发布与定时监测另行授权。
